# Strata art pipeline (pilots P1 and P2)

Both pilots from `strata_outline.md` §4.3 are done. Everything is generated by
scripts in `tools/strata/`. Run them from the repo root, and commit the outputs.

## P2: era palettes for battle backgrounds and the grass overlay

**What it does.** In a deep-time map, the battle background and the tall-grass /
long-grass / shaking-grass / ripple / ash field effects now use the same colour
transform as that era's overworld tilesets. Without this they kept Hoenn colours.

| Era | Transform | Maps |
|---|---|---|
| `ERA_IMPACT_WINTER` | `impact_winter` | Levee/River/Backswamp (winter) |
| `ERA_BIGHORN_PETM` | `petm` | Red Beds |
| `ERA_WHITE_RIVER` | `oligocene` | White River |
| `ERA_TRAP_CAVE` | `ice_age` | Steppe, Trap Cave |
| all other eras | stock | |

**Data.** `python3 tools/strata/gen_tilesets.py` writes the tileset variants (as
before) and also:

- `graphics/battle_environment/strata/<transform>/<env>.pal`: the 9 outdoor
  environments (tall grass, long grass, sand, underwater, water, pond, rock, cave,
  plain). Colour 0 of each 16-colour bank is kept.
- `graphics/field_effects/palettes/strata/general_1_<transform>.pal`: the shared
  `FLDEFF_PAL_TAG_GENERAL_1` sprite palette.
- `src/data/strata_era_art.h`: the tables. The era→transform map is
  `ERA_TRANSFORMS` and the environment list is `BATTLE_ENVS`, both in `gen_tilesets.py`.

**Engine.** `src/strata_art.c` looks up the current map in `sStrataMapEras`
(`src/data/strata_map_eras.h`, generated by `gen_maps.py`). It uses the map
and not `VAR_STRATA_ERA`, so the art always matches the tileset on screen. The hooks:

- `battle_bg.c`: both battle-background palette loads go through
  `Strata_GetBattleEnvironmentPalette()`.
- `field_effect.c`: the three field-effect palette loaders go through
  `Strata_GetFieldEffectPalette()`. So does the grass palette of the
  overworld-encounter spawn animation (`wild_encounter_ow.c`). This swaps only
  `GENERAL_1`.

**Adding an era** (e.g. after A1 adds a `paleocene` transform): add the transform
to `TRANSFORMS`, map the era in `ERA_TRANSFORMS`, rerun `gen_tilesets.py`. No C changes.

**Preview.** `python3 tools/strata/gen_tilesets.py --preview DIR` writes
`battle_bg_<env>.png` and `tall_grass_overlay.png`. Each shows stock first, then
each transform.

**Limits.**
- `GENERAL_1` also colours ripples, ash and hot-spring water, so they shift too.
  That is the intended result: they sit on the same ground.
- A sprite palette stays loaded until the overworld resets sprite palettes, which
  happens on a warp. A *map connection* between maps of different eras would keep
  the old grass colour until the next warp. Today every era change is a rig warp.
- The transforms are global colour maps. The impact-winter battle BG is almost grey,
  matching the tileset. New background *art* (badland cliffs, ash) is still task A6/§4.1.
- Stadium, building and legendary environments are untouched.

## P1: procedural creature sprites (`gen_sprite.py`)

`python3 tools/strata/gen_sprite.py [name ...] [--preview DIR]` writes, for each
species in `SPECS`, into `graphics/pokemon/strata/<name>/`:

| File | Format |
|---|---|
| `anim_front.png` | 64×128 (two 64×64 frames), 4bpp indexed |
| `back.png` | 64×64, same palette |
| `normal.pal`, `shiny.pal` | JASC, 16 colours, index 0 transparent. Shiny is a "pigment variant": hue/saturation shifts of chosen ramps |
| `icon.png` | 32×64 (two frames), indices into one of the 6 shared icon palettes. The best fit is picked in CIELAB, and the outline always maps to the icon dark grey |
| `footprint.png` | 16×16 1bpp (blank for fish) |
| `CUSTOM` | marker plus presentation overrides (`frontPicSize`, `frontPicYOffset`, `backPicSize`, `backPicYOffset`, `iconPalIndex`), measured from the art |

**gen_species.py integration.** If `CUSTOM` exists, `gen_species.py` does not copy
the borrowed species' graphics over the folder. It also replaces the matching
borrowed presentation fields with the `CUSTOM` lines. Everything else (animation,
shadow, cry) is still borrowed. The roster needs no `art=` field, and deleting
`CUSTOM` reverts to the borrowed sprites. Run `gen_sprite.py`, then
`gen_species.py`, then build.

**How a sprite is made.** A species is a Python function `name(phase)` that returns
a `Model`: a list of `Part`s, the colour ramps (≤15 colours including the outline),
and optional `details` / `post` painters. Phase 0 and 1 are the two front frames.

1. Shapes are in sprite pixels, centred on the origin, head to the left:
   `Ellipse`, `Tube` (capsule chain: limbs, tails), `Loft` (a body lofted along x
   from top/bottom profile curves: fish, torsos), `Union` (smooth union shaded as
   one dome), `Poly` (flat fins, frills).
2. Coverage: 4×4 supersampling per pixel. The nearest part covering half a pixel
   owns it.
3. Shading: each part is a dome, with the normal taken from the gradient of its
   inside-ness field and `flat` controlling how round it is. The light comes from
   the upper left. The result is quantised into the part's ramp, or into a
   per-point `region` ramp for countershading. Nearer parts cast a 1-px shadow onto
   farther ones.
4. Contours: a nearer part draws its `inner` colour where it overlaps a farther part.
5. `details` paint eyes, mouths, fin rays, operculum, scutes, fur dashes, toes.
6. A 1-px outer outline in each part's `outline` colour.
7. `post` handles anything drawn over the outline (whiskers).

The back sprite is the same model rendered mirrored, slightly larger, with the
light still from the upper left. The icon is the model at about 0.5 scale, where
`details` drop the fine features (`cv.scale < 0.8`).

**Previews** (`--preview DIR`): `<name>_sheet.png` shows front frames, back, shiny
front and back, and icons, at 1× and 3×. `<name>_front_x6.png` shows both front
frames at 6×. `<name>_battle.png` shows the creature as foe and player mon on the
tall-grass battle BG, in stock and impact-winter palettes, at Emerald's battler
coordinates.

### Adding the next creature

1. Copy the closest function. `knightia` is the fish template (loft body, fins as
   polys). `mesodma` is the small-quadruped template (union torso, head + snout,
   near/far legs as tubes, tail).
2. Set proportions from the real animal. Note the evidence and the speculative
   choices in the docstring (fur colour, ears, soft tissue).
3. Choose ramps: an outline, 3–4 shades for the main colour, 3 for a
   belly/secondary, 2–3 for skin/fins, one or two accents. That totals ≤ 15.
4. Add a `SPECS` entry: front, back and icon scales, the shiny ramp shifts, and a
   footprint.
5. Iterate with `--preview` until it reads at 1× and 3×. The script stops if the
   art exceeds 64×64.
6. Run `gen_species.py`, then `make`. Check `git diff` on `strata_families.h`:
   only the 5 presentation lines should change.

Expect 30–60 minutes per species for a variant of an existing template, and a few
hours for a new template (biped/theropod, bird, turtle, ray, bat, proboscidean).

### Lessons and limits

- **What works:** silhouettes, consistent lighting and outline style, honest
  colour choices, perfect format compliance, and instant re-renders when the
  science changes (e.g. a longer tail). At 1× the two pilots read clearly as "a
  herring" and "a mouse-like mammal".
- **Global lighting needs tuning per ramp length.** A surface facing the viewer
  should land on the second-lightest shade, or bodies go flat.
- **Painted details carry the appeal**: the eye, the mouth line, the contour
  between head and body, fin rays. They are hand-placed in model coordinates, so
  each species still needs an artist's eye.
- **Limits:** everything is a side profile. Pokémon front sprites are usually 3/4
  views, and back sprites here are mirrored profiles, not true rear views. The
  two-frame animation is a small pose change. There is no hand-pixel cleanup
  (jaggies, clusters, anti-aliasing). Complex anatomy (horn/frill, feathers,
  armour, shells, wing membranes) needs new primitives and textures. Icons are
  limited by the 6 shared icon palettes: brown/olive creatures fit well, but
  strong blues and reds fit poorly.
